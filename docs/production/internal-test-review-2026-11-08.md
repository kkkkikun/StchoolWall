# 开发人员封闭内测检查：2026-11-08

对象：https://sw.kkkkikun.dpdns.org/ 。目标是少量开发人员使用合成数据测试Web功能。通过用户授权SSH只读检查宿主机、容器配置、数据库聚合状态和HTTP响应；没有更改服务器配置、重启服务、注册账号、发布内容、执行迁移或压测。报告不保存任何密码、令牌、密钥、用户内容或学生资料。

## 结论

服务具备开始小规模功能验证的基本运行条件，但应先封闭访问入口。当前为专门的staging内测镜像，允许游客互动、待审内容自动通过、本地保存证件，反向代理未配置人员白名单。这些便利开关只能用于受限访问、合成数据的开发内测。

本轮无需先完成小程序/安卓上架、全校容量或生产级WAL演练。正式生产的安全、数据保护、资质及发布验收仍保留，不因本次检查而通过。

## 开始内测前优先完成

### 1. 限定测试人员与更换已披露凭据

- SSH root密码已出现在会话中，应更换。已有authorized_keys；先验证个人SSH密钥在第二个连接可登录，再安排关闭root密码登录或改用具备sudo的个人账号，避免锁住管理员。
- 在云安全组收紧SSH来源。应用入口使用VPN或开发人员固定出口IP白名单，覆盖学生端、PC端、管理端及/api，保留证书续期。未在应用/代理配置中发现此限制；UFW当前未启用，但这不等于云安全组没有防护。
- 若人员网络经常变化，优先经受控VPN访问。单纯隐藏URL不构成访问控制。全站Basic Auth会与现有API Authorization: Bearer争用请求头，不能直接套上而不验证。
- 不改动与本项目共享Caddy的openfeedback站点。修改前先备份对应配置并验证Caddy配置可加载，再独立验证新连接与另一站点。

验收：测试人员可以访问，非白名单网络被拒绝；SSH新凭据成功，旧密码失效。

### 2. 只用合成资料，明确内测开关

实际设置：ENVIRONMENT=production、DEPLOY_ENVIRONMENT=staging；DEV_LOGIN_ENABLED=false；ALLOW_GUEST_INTERACTION=true、AUTO_APPROVE_MODERATION=true、VERIFICATION_ALLOW_LOCAL_IN_PRODUCTION=true；STUDENT_VERIFICATION_ENABLED=true；公开与证件存储均local；腾讯审核未配置。

- 内测只使用虚构昵称、测试学号、合成图片与明确标注的测试证件。当前不要接收真实学生证或学生个人资料。
- 不测试认证时关闭学生证入口；需要验证认证时仅用合成材料，并验证只有审核员可看原图、访问被审计、期限与注销删除生效。
- AUTO_APPROVE_MODERATION会提升原本review的结果，不能把此时发布成功记为真实机器审核验收。保留一轮关闭该开关后的待审→人工决定测试；旧review任务也需人工判断处理，不能一键视为全部合格。
- 正式部署前关闭全部内测放宽开关，恢复学籍权限与审核保护，再做专项回归。

验收：全部参与者清楚数据可清空；无真实证件；游客/认证学生/管理员三种权限均有记录。

### 4. 修正可信代理IP

当前链路是Caddy容器→sw-edge网络→API，不是宿主Nginx→Docker网关。检查时Caddy在该网络为172.19.0.3，API为172.19.0.2；API却只信任FORWARDED_ALLOW_IPS=172.30.0.1。Uvicorn启动已启用proxy-headers，CLI未另行覆盖信任列表。

应信任实际、固定的Caddy源地址或改造为可稳定识别的受控代理链；不要简单设为*或信任全部私网。容器动态地址可能随重建变化，调整时同时验证网络与地址分配。Caddy当前覆盖X-Forwarded-For，这部分正确。

验收：两个真实外网来源分别累积自己的登录限流计数；伪造X-Forwarded-For不能替换来源；不能所有开发人员共享Caddy的额度。此次只发现配置不匹配，没有主动消耗登录额度来复现429。

- 未发现本项目备份timer/cron，在/opt/schoolwall-cn、/var/backups、/root限定深度内也未找到逻辑备份。云快照、外部备份系统及更深目录未核验，因此结论是尚无可验证备份证据。

验收：存在异机备份与一次恢复记录；主动制造无害探针失败能收到通知；升级失败能找到上一版本。

## 一轮可执行的内测范围

1. 开发人员用浏览器、手机浏览器各跑一遍注册/登录、刷新、退出、改密与另一设备撤销。
2. 合成认证资料→人工审批/驳回；普通用户不能看证件；过期与注销后的材料不可读取。
3. 发帖/多图顺序、评论、点赞、组局名额、举报、拉黑、通知、申诉；记录重复操作和弱网结果。
4. 关闭自动放行后验证待审/人工审核；在安排的窗口重启worker，确认任务能继续处理。
5. 统一记录版本、浏览器、操作步骤、预期/实际结果和request_id；截图先遮掉凭据与个人资料。

开发人员自行商定观察期与可接受的数据丢失范围；先积累一轮功能、权限、恢复证据，再考虑扩大人数。此清单不构成正式生产、真实学生数据、平台审核或容量验收通过。
