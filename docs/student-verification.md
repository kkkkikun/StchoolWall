# 学生证认证：部署与删除验收

本模块面向单校人工认证试点。默认关闭 `STUDENT_VERIFICATION_ENABLED`；配置、权限与下列验收未完成时保持关闭。认证照片只进入独立私有桶，不进入公共上传桶、CDN、静态目录或腾讯内容审核。管理员须通过后台 MFA，查看原图产生审计记录；前端 Blob 预览关闭时释放。

## 数据和认证规则

- 一次挑战绑定当前账号，10 分钟有效；照片须同框显示学生证和本次随机码，提交成功后挑战单次消耗。人工审批须核对学校、随机码、卡面学号与有效期。
- 学号仅在上传及复核请求内处理。数据库只保存学校 ID、版本化 HMAC 指纹和认证状态；不保存学号原文或姓名。应用日志、代理访问日志、APM/错误上报不得采集这些请求体或照片。
- `VERIFICATION_FINGERPRINT_KEY` 使用独立随机密钥，不能复用 JWT、媒体签名或其他密钥。轮换时设置新 `VERIFICATION_FINGERPRINT_KEY_VERSION`，旧密钥放 `VERIFICATION_FINGERPRINT_PREVIOUS_KEYS` 的 JSON 版本映射中。旧版本仍有有效认领时必须保留，以防跨版本重复认领；丢失旧密钥须停止新认证并进行人工迁移。密钥通过独立密钥管理存储与恢复，不写入仓库。
- 认证最迟 12 个月到期；卡面日期更早时提前到期。到期降为游客，需重新认证。拒绝、到期、撤销的申诉不恢复权限，需管理员依事实另行处理。
- 已占用学号的提示保持通用，不透露另一个账号。跨端账号使用本人配对码绑定登录身份，不能按学号自动合并。

## 私有 COS 桶硬要求

生产设置 `VERIFICATION_STORAGE_PROVIDER=cos` 和独立的 `VERIFICATION_COS_BUCKET`。该桶必须与 `COS_BUCKET` 公共媒体桶分离，禁止公共 ACL/公共策略、CDN、静态网站、跨桶复制、跨区域复制、数据同步、备份任务及第三方扫描。禁止对象锁定、WORM、法定保留和冻结导致删除无法完成的策略。凭据仅授权本桶必要操作，不授予公开 ACL/策略配置权限。

上传时应用检查桶 ACL、公共策略、版本控制和复制设置，不满足条件则拒绝上传；对象使用 private ACL 和服务端 AES256 加密。生产服务角色需要读取这些配置的权限，缺失权限不能绕过检查。代码无法发现账号外部的人工备份或云平台所有同步任务，部署负责人须检查控制台及组织级策略并留验收证据。

禁用版本备份：新建从未启用版本控制的独立桶优先。已启用过的桶仅暂停版本控制不会删除历史版本，须先停写并清除全部历史版本与删除标记再验收。删除函数枚举精确对象 key 的所有版本及删除标记，仅删除完全相同的 key，不误删同前缀对象。即使桶误启用了版本控制，清理仍可尝试物理清除；清理失败不清空数据库引用，交由重试及告警处理。

上线验收（使用测试证件，禁止真实学号）：

1. 公共域名、无鉴权 COS 请求、普通用户及未通过 MFA 的管理员无法读取照片。正式 CDN 不包含证件桶。
2. 上传测试照片并检查对象无 EXIF、私有 ACL、服务端加密；普通 UGC 审核服务日志中没有该照片。
3. 验证开启版本控制、复制规则或公共策略后上传失败；关闭这些设置后恢复。不得在真实证件桶开启设置进行测试，使用隔离桶。
4. 隔离桶中为同一 key 生成多个版本和删除标记，并创建同前缀不同 key；执行删除后精确 key 的对象、版本、删除标记均为空，另一 key 完好。无版本控制桶也须验证对象确实不存在。
5. 用云控制台、独立只读验收凭据检查版本/复制/备份/对象锁配置并归档结果；只运行构建或 mock 测试不能替代实际 COS 验收。

## 生命周期、注销与恢复

`cleanup_expired_verifications(db)` 由独立 worker 约每 60 秒运行，自行提交。待审提交超过 14 天自动过期并删除证据；审核结果产生后原图保留 7 天，认证权限仍持续到认证有效期；注销将所有申请撤销并将证据删除时间设为当前时间。不存在额外缩略图副本。上传成功但数据库回滚形成的孤儿对象在超过 14 天后删除；扫描不记录学号原文。

生产必须监控 worker 心跳、清理失败与过期未删数量；数据库已到删除时间不等于物理删除成功。删除失败（权限、对象锁、网络等）必须告警并重试；不得将失败标记为已删。停机后恢复 worker 会继续处理到期对象。

数据库备份不包含证件对象或私有本地目录；证件桶禁止版本、复制及任何备份。恢复旧数据库前先保持认证与发布关闭，恢复后立即运行一次清理，再启动定时 worker并核验已到期的对象。已物理删除的照片不会因数据库恢复复活，管理员查看旧引用返回 404。若外部备份仍存有证件，代码无法证明删除完成，必须先清除此类副本并完成恢复演练才允许上线。

## Web / 小程序 / Android 会话及隐私门禁

Web access token 仅内存，refresh 在 HttpOnly Cookie；携带凭据及双提交 CSRF，禁止把 Web refresh 存入 localStorage。小程序使用平台存储，Android refresh 只存 AndroidKeyStore AES/GCM 加密数据；安全存储不可用时拒绝建立登录态。Android 设备加密密钥不可迁移；清数据或重装后须重新登录。

Android 编译产物不是可分发 APK。须用与 CLI 同版本的 HBuilderX 打包，替换 `androidPrivacy.json` 中正式已备案 HTTPS 政策域名，填写真实主体、联系方式、全部 SDK 清单及用途/收集范围/权限/触发时机，并核查实际 APK 合并 manifest。当前模板只请求网络、网络状态和拍照所需权限，拍照须在用户主动认证时触发。

使用 DCloud 官方 template 隐私模式；拒绝时退出，不启用游客 SDK 初始化。必须在真机抓包和权限审计中验证首次同意前、拒绝后、撤回同意后没有非必要 SDK 初始化或信息采集，并测试 AndroidKeyStore 在目标 Android 版本上的存取、重装和异常行为。Web/小程序真实登录、OAuth state、Cookie 跨域/HTTPS、双标签刷新及双端撤销也须在正式域名隔离环境回归。Web 会话通过 BroadcastChannel 只在同源标签页内存同步新 access token/CSRF 和退出；刷新持有 Web Locks 原子锁，并在锁内向同源标签同步最新会话，避免轮转刷新相互失效。Web Locks 或 BroadcastChannel 不可用时禁止自动 Cookie 刷新并提示重新登录，须将安全上下文及支持两项能力的浏览器列为 H5 登录准入条件。无锁兼容降级不得上线。
